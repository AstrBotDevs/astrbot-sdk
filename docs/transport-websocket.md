# WebSocket Transport (v1)

The SDK protocol (protocol-v1) is transport-agnostic: every frame is one
self-delimiting JSON document. stdio is the default transport for
host-spawned local runners. The WebSocket transport exists for runners that
AstrBot cannot spawn — plugins running on another machine, in a container, or
implemented by a future non-Python SDK (`runtime.language`).

## Topology: runner dials out, host listens

```
┌─────────────┐   ws(s)://host:6195   ┌──────────────┐
│   Runner    │ ──── connect ───────▶ │  WS listener │
│ (any host)  │ ◀── protocol frames ─ │ (core proc.) │
└─────────────┘                       └──────────────┘
```

- The host runs **one shared listener** inside the core process
  (default `127.0.0.1:6195`, configurable). All external plugins share it.
- The runner dials out. NAT/containers only need outbound connectivity from
  the plugin side; the core side needs one reachable port.
- Direction of protocol traffic is unchanged: Host→Runner `invoke`,
  Runner→Host capability calls, both multiplexed over the same socket.

## Authentication

- Each external plugin gets a per-plugin **bearer token** (generated by the
  operator, e.g. `openssl rand -base64 32`).
- The runner sends it as `Authorization: Bearer <token>` during the HTTP
  upgrade. The listener validates it **before accepting** the socket and
  answers `401` on mismatch — no protocol traffic ever flows on an
  unauthenticated connection.
- Tokens map 1:1 to a pending external plugin entry; a token is single-use
  per live connection (a second dial-in with the same token replaces nothing
  and is rejected while a connection is active).
- For anything beyond a trusted network, use `wss://` (TLS is handled by the
  URL scheme; certificate verification follows the platform defaults).

## Framing

- One WebSocket **text** message carries exactly one protocol frame
  (`encode_frame` output, UTF-8 JSON). The newline terminator is kept so
  stdio and WS share one codec.
- Message size limit equals `MAX_FRAME_BYTES` (8 MiB) on both ends.
- Protocol-level ping (`ping` method) and supervisor health checks work
  unchanged; the WebSocket keepalive is left at library defaults.

## Runner CLI

```
python -m astrbot_sdk.runtime --ws ws://core:6195 --plugin-root . [--legacy]
ASTRBOT_RUNNER_TOKEN=<token>  # env, never argv (keeps it out of ps)
```

`--stdio` and `--ws` are mutually exclusive; stdio remains the default for
host-spawned runners.

## Host wiring (core)

External plugins are declared in host configuration (deployment concern,
never in plugin metadata):

```json
{
  "listen": "127.0.0.1:6195",
  "plugins": [
    {
      "name": "astrbot_plugin_foo",
      "plugin_id": "author/foo",
      "token": "...",
      "legacy": false,
      "capabilities": ["storage.kv", "message.send"],
      "config": {}
    }
  ]
}
```

- `plugin_id` is validated against the handshake; a token cannot be used to
  mount a different plugin.
- `capabilities` is the host-side allowlist granted at initialize (legacy
  plugins use the built-in legacy grant set instead).
- Lifecycle mirrors the process supervisor: unexpected disconnect marks the
  plugin down and the bridge waits for a redial with backoff/circuit
  breaking; a deliberate stop closes the socket without waiting.

## Non-goals (v1)

- mTLS / per-connection ACLs beyond the bearer token.
- Multiplexing several plugins over one socket (one socket per plugin).
- Host-spawned runners over WS (stdio already covers local spawn).
